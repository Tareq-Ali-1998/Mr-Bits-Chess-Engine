The exported C++ evaluators live in ../engines/Neural Networks/. The short neural evaluation and sorting complexity guide explains the exact bounds for Small and Large. The Kernel families organize the experiments into legacy handcrafted leaves (v1.0.x), legacy neural leaves (v1.1.x), and legal/quiescence search (v1.2.x). The version map records every previous label and its current name. Read the short v2.1/v2.2 guide for the full-width and late-move-reduction pair.

The newer v3.0 guide covers independent legal generation, mate/stalemate, bounded quiescence, and improved iteration admission. Its original-copy source remains separate from all earlier versions.

Read the new guides in this order: How V3.0 works — five illustrated parts, Small/Large operation counts and sorting cost, then V3.1 — pure Small static evaluation.

Start the scoring comparison with v3.1: 100% Small, v3.2: 100% handcrafted, v3.3: 80% Small / 20% handcrafted, and v3.4: 20% Small / 80% handcrafted. All retain v3.0's search behavior. The pure-Small v3.1 was reused, so v3.5 is intentionally absent.

Next experiments: V3.6 — Large top-three with original scoring, V3.7 — Large top-three with blended scoring, and V3.8 — PVS plus exact static-value caching. Their short illustrated guides explain the policy, costs, and limitations.

V3.9 — Small top-ten above depth two keeps V3.0's scoring and legal/tactical foundation while testing a narrower ordinary tree. At depth two or less, including quiescence, it performs no move sorting. The temporary old v7 folder has been retired; select v3.0 for that same baseline. The proposed search-table design, previously called V13, waits for a worker-memory discussion before implementation.

The V13 memory proposal accounts for all 28 workers together and distinguishes fixed allocations from an estimated RAM allowance. V13 remains a design to discuss, not an implemented kernel.

Inspect the game database

Double-click Launch Dashboard.bat in lichess-bot-master to open http://127.0.0.1:8765/. The read-only visual portal shows recorded games, moves, search metrics and version comparisons with five-second refresh. Dashboard instructions.

The local file is ../database/mrbits.sqlite. Existing CLI inspection remains available:

python database\db.py --check
python database\db.py --recent 40

Full replay and finished outcomes require both sides' stored moves/results from the existing Lichess sync. Missing records stay empty; the viewer does not invent them.
